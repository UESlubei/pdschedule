# 优化实验运行与恢复

实验采用独立后台 Session，避免交互终端中断后失去运行器。启动器可重复调用，已有本项目主进程时直接返回 PID：

```bash
cd /home/sdn/wjh/Ondeviceinfer/source/adaptive_prefill_budget
/home/sdn/anaconda3/envs/ljc/bin/python scripts/launch_optimization.py
```

运行目录为 `/mnt/ondeviceinfer/experiments/adaptive_prefill_budget_v0320_opt2`。

- `recovery-master-pid.json`：后台主进程 PID。
- `recovery-master-status.json`：当前阶段、开始时间、失败日志或完成结果。
- `logs/recovery-master.log`：阶段切换记录。
- `opt_validation-status.json`、`opt_match1536-status.json`：服务进度。
- `manifests/*-protocol.json`、`snapshots/`：冻结参数与源码。

主运行器依次完成五种子验证、同预算三种子对照、五组 Nsight 节点采集、数据审计、权重/来源校验、报告与交付快照。每个GPU阶段使用项目锁和既有项目的GPU锁，所有策略串行运行。已有 `completed.json` 的服务必须通过审计才跳过；未完成服务不得伪造为完成。

如意外终止发生在一个种子中间，应先查看进程、请求数和日志。只清理确认属于本项目且已失去运行器的孤立服务；保留原始产物。若同轮策略之间出现长时间断层，整轮归档后按原协议重跑，排除原因和数据量写入 `interruptions/`，不能按性能好坏选择保留。

2026-10-20 的恢复归档为 `interruptions/20261020-1830/`。三个完整种子保留，seed317的两个已完成服务（8个Trial）归档后整轮重跑。恢复过程未改变在线代码和模型。
